## 大改造：备婚流程自定义 / 导出 / 并发保护（v2.0.3）
- **步骤模板可编辑**：`weddingSteps.ts` 的 `WeddingStep.todo/prepare` 从 `string[]` 改为 `WeddingItem[]`（`{id, text}`）。默认项 id 用原序号 '0'/'1'，保证老 checked/notes 的 index key 无缝兼容；新增项用随机 id。新增 `cloneWeddingSteps()` 深拷贝模板。
- **前置沟通事项**：针对用户异地情况，在求婚/见父母/提亲/定婚期/预算 5 步各加了 1-2 条「两人先谈拢」的待办（定居城市、彩礼底线、见面礼、异地往返成本等），新增项用描述性 id 避免串位。
- **state 扩展**（`db.ts`，仍是 jsonb 无 migration）：`steps: WeddingStep[] | null`（自定义流程）、`locks: Record<string,{who,at}>`（编辑锁）、`rev: number`（版本号）。所有旧字段读取均兜底。
- **并发保护**：核心 `mutateWedding` 改成「fetch 云端最新 → 深拷贝副本上应用变更 → rev+1 → upsert」，避免整块覆盖。锁按 `weddingItemKey` / `step:<id>` 粒度，60 秒 TTL，对方锁定时只读并提示 🔒TA；mutate 时顺带清理过期锁。**关键坑**：保存内容与解锁必须写在同一笔 mutate 里（让 saveWeddingNote / saveWeddingStep / editWeddingItem 内部删锁），否则两次并发 fetch-write 会互相覆盖。
- **增删改 UI**：`WeddingCheckList` 每条待办支持备注/改文案/删除/新增；大步骤标题行有 ✎/🗑，底部「+ 新增一个大步骤」。首次编辑时 `ensureWeddingSteps` 把模板落到 state。
- **导出**：顶部「⬇ 导出流程」生成排版文本（总进度 + 每步状态 + [x]/[ ] 待办 + 备注），带 UTF-8 BOM，Blob 下载 `备婚流程_YYYY-MM-DD.txt`。
- **进度条置顶**：卡片顶部醒目渐变条 + x/y 步 + 百分比，总数用动态 `weddingTotal`（不再用常量 WEDDING_TOTAL）。
- typecheck + build 通过，dist 已更新。
