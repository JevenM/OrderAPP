## 新增四个功能（v2.2.0）
用户从「参考 toge-api 仓库列出的候选清单」里选定 #2 / #11 / #13 / #14，逐步实现：

1. **关系温度计**（零新增表）：`lib/warmth.ts` 纯计算 + `components/couple/WarmthCard.tsx`，放在互动入口页顶部（不是模块格子）。六路信号权重 三餐25/留言20/一起玩15/心意15/投喂15/动态10，各带 7 天满分阈值；采集 14 天在内存切「本周/上周」算趋势。数据由 `db.loadWarmthInput()` 十路并发取，任一失败只让该项计 0（`isMissingTable` 降级）。
2. **共建目标**：新表 `couple_goals`（迁移 0049），一个目标一行，kind = save/travel/habit/custom；习惯的打卡日期存 `checkins` jsonb 数组，连续天数前端算。写操作用 `updated_at` 当乐观锁，`patchCoupleGoal` 返回 false 表示对方刚改过。
3. **我们的常点榜**：`lib/dishRank.ts` 从 `orders + order_items`（近 180 天、排除 cancelled）聚合，榜单分 = 次数 × 90 天半衰 × 评分系数；推荐分不带衰减但要跳过最近 3 天吃过的，另有「摇一个」。
4. **逐菜评分**：新表 `couple_dish_ratings`（迁移 0049），唯一键 `(order_id, dish_name, rater_id)`，入口在 `OrdersPage` 订单详情、仅 `status='done'`。评分可改，平均分喂给常点榜。

### 踩坑与结论
- **评分不能挂 `order_items`**：`updateOrder` 会 delete 后重插明细，任何一次「编辑这单」都会抹掉评分且行 id 变化。独立表 + `dish_name` 快照做键才能存活。
- **`db.isMissingTable` 漏判纯对象错误**：原先只认 `Error` 实例，PostgREST 返回的 `{code:'PGRST205', message:'Could not find the table...'}` 被 `String()` 变成 `[object Object]`，导致「表没建」被当成真错误抛出、整个常点榜加载失败。已改为同时认 `code === 'PGRST205' | '42P01'` 和对象上的 `.message`。
- **`loveTree.ts` 的 `interp` 改为导出**：温度曲线复用同一份分段线性插值，避免第三份实现。
- **习惯卡片的 7 个方块 + 右侧「连续 N 天」在 320px 会重叠**：连续天数本来就在副标题里，删掉右侧文字、方块改 `flex-1` 撑满即解决。
- **无头截图出旧帧**：`Page.captureScreenshot` 在后台窗口会返回上一帧，必须先 `Page.bringToFront` + 重置一次 `Emulation.setDeviceMetricsOverride` 再截。
- **`sessionStorage['couple-active-module']` 会记忆上次模块**：用 CDP 验证入口页时要先清掉，否则永远进的是上次那个模块。
